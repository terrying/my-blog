### Ivanti Connect Secure &lt;&#x3D; 22.8R2.4 - Authentication Bypass via X-DSCGI-PATH Header

- **漏洞ID**: `CVE-2026-104935`
- **CVE**: `CVE-2026-104935` (2026)
- **严重程度**: 🔴 CRITICAL
- **风险等级**: 极高风险 (5/5)
- **影响资产**: 未知
- **预估影响**: 数千个


**描述**: Ivanti Connect Secure VPN appliances contain an authentication bypass vulnerability in how the appliance routes requests from front- and back-end processes to CGI script handlers. The URL path is used to determine whether a request is allowed (welcome.cgi is public), while the X-DSCGI-PATH header determines the actual destination of the request. An attacker can send a request to the unauthenticated welcome.cgi endpoint with an X-DSCGI-PATH header pointing to an authenticated CGI script such as wu.cgi, bypassing authentication entirely. This vulnerability is chained with a file write race condition in wu.cgi and a privilege escalation via dsinvoked DSCache trust to achieve unauthenticated root-level remote code execution.


**攻击向量**: 网络扫描

**CVE编号**: CVE-2026-104935

### Chef Automate API Gateway - Authentication Bypass

- **漏洞ID**: `CVE-2026-80462`
- **CVE**: `CVE-2026-80462` (2026)
- **严重程度**: 🔴 CRITICAL
- **风险等级**: 极高风险 (5/5)
- **影响资产**: 未知
- **预估影响**: 数千个
- **EPSS**: 0.00483 (percentile 0.39876) @ 2026-10-13

**描述**: Chef Automate derives an internal service identity from an X.509 certificate supplied in a request header without verifying its issuer. The load balancer blanks X-Client-Cert but does not strip the Grpc-Metadata- prefixed variants, which grpc-gateway rewrites into the metadata key the gateway&#x27;s auth middleware reads. A remote unauthenticated attacker can present a self-signed certificate naming an internal service such as deployment-service and be authenticated as that service.


**攻击向量**: 网络扫描

**CVE编号**: CVE-2026-80462

- **CVE**: `CVE-2026-2413` (2026)
- **严重程度**: 🟠 HIGH
- **风险等级**: 极高风险 (4.5/5)
- **影响资产**: WordPress 站点
- **预估影响**: 数千万个
- **EPSS**: 0.02331 (percentile 0.83112) @ 2026-10-13

**描述**: The Ally – Web Accessibility & Usability plugin for WordPress is vulnerable to SQL Injection via the URL path in all versions up to, and including, 4.0.3. This is due to insufficient escaping on the user-supplied URL parameter in the `get_global_remediations()` method, where it is directly concatenated into an SQL JOIN clause without proper sanitization for SQL context. While `esc_url_raw()` is applied for URL safety, it does not prevent SQL metacharacters (single quotes, parentheses) from being injected. This makes it possible for unauthenticated attackers to append additional SQL queries into already existing queries that can be used to extract sensitive information from the database via time-based blind SQL injection techniques. The Remediation module must be active, which requires the plugin to be connected to an Elementor account.


**攻击向量**: 网络扫描

**CVE编号**: CVE-2026-2413
