### GitLab - SAML Authentication Bypass

- **漏洞ID**: `CVE-2025-25291`
- **CVE**: `CVE-2025-25291` (2025)
- **严重程度**: 🔴 CRITICAL
- **风险等级**: 极高风险 (5/5)
- **影响资产**: GitLab 平台
- **预估影响**: 数千个
- **EPSS**: 0.19506 (percentile 0.97094) @ 2026-07-29

**描述**: ruby-saml provides security assertion markup language (SAML) single sign-on (SSO) for Ruby. An authentication bypass vulnerability was found in ruby-saml prior to versions 1.12.4 and 1.18.0 due to a parser differential. ReXML and Nokogiri parse XML differently; the parsers can generate entirely different document structures from the same XML input. That allows an attacker to be able to execute a Signature Wrapping attack. This issue may lead to authentication bypass. Versions 1.12.4 and 1.18.0 fix the issue.


**攻击向量**: 网络扫描

**CVE编号**: CVE-2025-25291

### SureForms &lt;&#x3D; 2.5.2 - Unauthenticated Payment Amount Validation Bypass via form_id

- **漏洞ID**: `CVE-2026-4987`
- **CVE**: `CVE-2026-4987` (2026)
- **严重程度**: 🟠 HIGH
- **风险等级**: 极高风险 (4.5/5)
- **影响资产**: WordPress 站点
- **预估影响**: 数千万个
- **EPSS**: 0.00256 (percentile 0.17213) @ 2026-07-29

**描述**: The SureForms plugin for WordPress is vulnerable to payment amount validation bypass in versions up to, and including, 2.5.2.
The create_payment_intent AJAX handler checks `if ($form_id &gt; 0 && !empty($block_id))` before calling validate_payment_amount().
By sending form_id&#x3D;0 (the default intval of a missing/zero value), an unauthenticated attacker completely skips the server-side
amount validation and can create Stripe payment intents with arbitrary amounts, bypassing configured pricing.


**攻击向量**: 网络扫描

**CVE编号**: CVE-2026-4987
